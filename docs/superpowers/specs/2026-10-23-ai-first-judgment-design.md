# AI 先判、你点行不行 设计文档

日期:2026-10-23
状态:方案已获用户同意("方案可以,写设计文档"),待用户审阅本文档

## 背景

用户的话:**"我还需要一个 AI 可以代替我判断,让我看看他的判断,然后我判断行不行,这样我的负担就最小,
而 AI 也可以拿到数据了。理由可以加也可以不加。尽可能减少用户的判断负担。"**
追问要不要留"先判断"时:**"当然可以留先判断。尽可能减少负担,才会有更多的真实信息进入。"**

现在的样子(10-16 的使用快照:系统产出很多,他写的判断、周刊、假门都是 0):
- **预测题**(/signals/forecast,「今天」的「等你判断」,早上邮件的一键档位):每道题他先点一档几成,
  点之前看不到 AI 和市场;可以"先看答案",看了这道就不能再判断(宪法原则 1 例外四 ④)。
- **每天的练习**(「今天」的"今天的练习"):先拆一拆(可选)→ 写一句判断、选期限、选把握、打标签 →
  交了才看 AI 的挑刺(`submitJudgment`,`critiqueJudgment`)。一道要几分钟,所以几乎没做。

难点不在信息不够,在于每一条都要他从头判断。改成 AI 先判、他只点一下,判断才会真的发生;
他改判的那几次,才是"他知道 AI 不知道的东西"的数据。

## 锚定这件事要写明

他点「行」的那一下不是他的判断,是 AI 的判断加他的认可 —— 看到现成答案十有八九会点行。
所以:
- 「行」的记录**不算他的分**,只算"他同意了 AI";
- 他自己准不准,只从**改判**和**每周一道先判**里数;
- 页面上写一句:"点「行」的不算你的分,那是 AI 的。"

## 一、预测题:AI 先判

### 卡片

每道等判断的题(AI 已经判过的)直接摆出:

```
[题目] · 市场题 · 2027-03-31 截止
怎么才算「会」:……
AI:三成会(按回测校准)        ▸ AI 的三种思路各说了几成、为什么
[行]  [不行,更高]  [不行,更低]  [跳过]
```

- 显示的数:AI 中间值(forecasts.source = ai);有校准(`applyPlatt`,回测学到且确实更准)时显示校准后的数,
  并照旧写「按回测校准」。理由折起来,点开才看。
- **市场的数照旧点完才显示** —— 改判比的是他和 AI,不是看着市场改。统计基准(base)写在题目上的照旧显示。
- 「行」:记 me = AI 显示的那个数(校准后的就记校准后的),mode = agree。
- 「不行,更高 / 更低」:展开那一边的几档(MY_TIERS 里比 AI 的数高 / 低的),点一档记 mode = override;
  可以补一句为什么(可以不写,存 forecasts.reason)。
- 「跳过」:不记,这道题从"等你判断"里拿走(记一条 forecast_reveals,和"先看答案"一样不能再判断)。
- AI 还没判完的题不进他的队列(后台一天两次,半天内会判完)。

### 每周一道先判

- 题目进账本时由代码定:**这一周(东京时间,周一开始)还没有先判题,这一道就是先判题**
  (forecast_questions.blind = true)。市场题、生意题、数据题……每天都在进,所以每周一道。
- 先判题照现在的样子:先点一档,点之前看不到 AI 和市场;"先不判断,直接看答案"照旧(看了就不能再判)。
  记 mode = blind。卡片上写一句:"这道先自己判,判完再看 AI 的。每周一道,量的是你自己准不准。"
- 朋友共用题库,先判题是同一道,各判各的。

### 早上邮件的一键

邮件里"先说你的判断"那一道:
- 先判题:照旧一排档位(一键记 blind)。
- 别的题:`AI 说三成会:[行] · 不行:[5%] [15%] | [50%] [70%] [85%] [95%]` —— 一键就完成。
  行 = 签名链接 v=agree;档位 = v=<概率>,由服务器按 AI 的数判是 override。
  行动链接(lib/action-links.ts,kind forecast)不加新种类,v 多认一个 agree。

### 记分(代码数,规则不变:不满 10 道只给件数,校准表每格不满 5 道不给比率)

预测页"记分"一块分成三份:

1. **AI**:所有对过账的题都算(和现在一样)。以后第四步学校准、学权重也用这一份。
2. **你改判的几次**:只看 mode = override 的题,"你更近 a 道 · AI 更近 b 道 · 一样 c 道"(两两比,
   `headToHead`),满 10 道再给两边平均分。这是最有用的一个数:你出手改判时,比 AI 准还是比它差。
3. **你先判的几道**:只看 mode = blind 的题,你的平均分、你和 AI、你和市场两两比、你的校准表。
   以前的判断(迁移前记的,mode 为空)全算先判 —— 那时本来就看不到 AI。

点「行」的不进任何一份"你的分",只数"你同意了 AI 几次"。
**一起练**(`compare.ts`,和朋友比平均分)只用先判和改判的题。

## 二、每天的练习:AI 先写一句

### AI 的那一句怎么来

- 后台(GitHub Actions 的 jobs,`forecast` 那一步之后加一步 `practice`)给当天报告的练习题出 AI 的判断;
  后台没做到的,第一次打开「今天」时补(放在 Suspense 里,报告先出来)。
- 做法照搬预测题:按题目上网查一次资料(`webSearch`),三种思路(先看基准率 / 只看这件事 / 唱反调)
  各押一个几成(`forecastFromPerspective`,题目 = 练习题,标准 = 题目下面的"到时候看什么",
  截止 = 题目里的日子,没有就按默认期限),至少两个押成了,代码取中间值。
- **那一句由代码拼,不让 AI 另写**:中间值 ≥ 0.5 写「会」,否则写「不会」,
  后面接题目原话和截止 ——「会。〔题目〕(到 2027 年 3 月底)」。把握按离 0.5 多远换成三档
  (CONFIDENCE_LEVELS:没什么把握 / 有点把握 / 很有把握,分界在 0.63、0.8)。
  三种思路的理由折起来给他看。
- 存在那一天 news 报告的 practice.ai_draft(和 practice.breakdown 一样,不加表):
  `{ probability, perspectives: [{ source, probability, reason }], made_at }`。

### 他点什么

```
今天的练习:〔题目〕
AI:不会,有点把握(到 2027 年 3 月底)      ▸ 为什么
[行]  [不行,我觉得会]  [跳过]
```

- 「行」:AI 那句原样进判断账本(predictions + signal_judgments),期限、把握照 AI 的,
  标签自动带「AI 先判」,mode = agree,ai_draft 存一份。**不挑刺** —— AI 挑自己的刺是车轱辘。
- 「不行」:方向反过来,句子先预填好(「会。〔题目〕」),期限和把握可以改,可以补一句为什么;
  交了记 mode = override,照旧送去挑刺(`critiqueJudgment`,同时告诉它 AI 原来判的是哪边、为什么)。
- 「跳过」:不记。
- "先拆一拆""看历史上类似的事""往下推"都还在,折在"想自己想一想"下面。

### 每周一天先判

- **每周一的练习是先判题**(报告生成时代码写 practice.blind = true,不出 AI 的那一句),
  照现在的样子:先拆一拆(可选)、自己写、交了看挑刺。记 mode = blind。
- 周一没做,那一周就没有先判的练习,不补、不催。

### 判断账本

- 判断账本(/signals/practice)每条标出是「你同意 AI 的」「你改判的」「你自己先判的」。
- 只数次数(原则 1:判断账本只记次数不算比率):三种各几条,对过账的三种各看对了几次。
- 到期对账照旧由他标看对了没有,"现在实际怎样"的证据照旧先查。

## 三、不动的地方

- **校准练习**(/signals/calibrate)、**历史题**(/signals/drill):答完马上揭晓,先给 AI 的答案就没有练的意义,
  照旧先判断。想练的时候去,不催。
- **生意题、到日本题到期确认**:本来就是程序给建议、他点确认。
- **自己实验的结果**(假门、周刊先猜):AI 没在猜这类题,这次不动。
- **他主动写判断的入口**(新闻详情页、在追的问题、往下推里「押这一条」、历史题揭晓后押今天那件事):
  是他自己想写才点进去的,照旧,记 mode = blind。
- **周刊点三下**:这次不动;以后可以照同样的办法让 AI 先填。

## 四、数据

迁移 099(同步追加到 schema.sql):

```sql
alter table forecast_questions add column if not exists blind boolean not null default false;
alter table forecasts add column if not exists mode text check (mode in ('blind', 'agree', 'override'));
alter table signal_judgments add column if not exists mode text check (mode in ('blind', 'agree', 'override'));
alter table signal_judgments add column if not exists ai_draft jsonb;
```

- mode 为空 = 迁移前的记录,一律当先判(那时看不到 AI)。
- 只有 source = me 的 forecasts 行有 mode。
- 099 没跑时:预测题和练习照现在的样子走(先判),页面提示跑 099。

## 五、宪法要改的两处(写明经用户明确裁决,2026-10-23)

- 原则 1 例外四 ④「他先押再看 AI 和市场,先看了就不能再押」改成:
  「AI 先判、他点行不行(行 = 同意,不行 = 改一档);每周一道先判题照旧先押再看。
  点行的不算他的分,他的分只从先判和改判里算;押了不能改。」
- signals 那一格"每天一道'先判断再看答案'的练习"改成:
  「AI 先写一句判断(三种思路取中,句子由代码拼),他点行 / 不行;每周一的练习照旧先判断、可以先拆一拆;
  点行的不挑刺。」

## 怎么判断有没有用

- 两周后看:预测题和练习各判了几道(现在接近 0)、其中改判几道、先判几道。
- 改判满 10 道以后看"你改判时谁更近"。如果一直是 AI 更近,说明改判多半是噪音;
  如果是你更近,说明那几类题上你有 AI 没有的东西 —— 这正是以后该多花心思的地方。
- 如果改判一直是 0,说明他只是在点「行」,那这个功能只是在帮 AI 攒数据。这本身不坏,但要直说。
