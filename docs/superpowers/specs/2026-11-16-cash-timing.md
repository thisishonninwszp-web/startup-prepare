# 假设现金流时间表（提案③）

经营案例内次级工具 /business-lab/cash，不新增导航或评分。让用户看到付款先后与现金余额变化，不下投资或财务建议。

本人选案例，填写标题、币种、起始日、期初现金及一组明确标为假设的入出金。每笔包含稳定id、日期、名称、in/out、最小币种单位整数金额、假设理由。JPY/CNY/USD/EUR只在各自场景内计算，不换汇；界面换算规则明确（JPY整数，其他币种两位小数），不用浮点金额运算。每项最多10^12最小单位、最多200项，期初同上，总和必须安全整数；日期严格有效Gregorian且限制合理范围。

保存、读取、编辑、删除、分页齐全。可以比较同一场景的baseline与alternative，两组都是本人仮定，期初/币种保持相同；修改 alternative 的收付款日/金额后由代码分别算。默认模板不得生成真实公司原价、销量或用户现金。缺金额/期间应要求补假设，不补经营事实。

计算按日聚合全部入出金后显示当日余额，不能用任意同日排序制造虚假的日内短缺。展示每一笔输入、逐日累计、首次日终为负的日期或“本组假设下未出现负数”、最低日终余额及两组对照。说明同日结算顺序未模拟。所有展示数值是假设的算术结果，不是想法得分或真实利润。窄屏表格可以水平滚动，不让整个页面溢出。

只做代码计算，无AI、抓取、定时和费用。存原始假设，加载后重新计算不信任客户端提交的结果。来源案例仅存id并按owner实时解析标题；不可用时保留本人情景并标记。版本冲突不可静默覆盖，保存失败保留输入，响应丢失可幂等重试。

文件：lib/domains/business-teardowns/cash/**、app/(app)/business-lab/cash/**、131_business_cash_timing.sql；公共入口和schema.sql由root整合。SQL安全/权限/金额/日期/数组限制与TS一致；测试真128迁移、同日收付/零/负余额边界、货币单位、日期、溢出、baseline一致性、owner、分页、冲突、重试及无核心验证表副作用。
