# 外部信号看得更快:一图看懂 + 带图的邮件 + AI 示意图 设计文档

日期:2026-10-18
状态:方案已获用户同意("方案可以,写设计文档"),待用户审阅本文档

## 背景

用户说外部信号"还可以更好":**内容可以更丰富,邮件里面也是;可以用图片生成,这样看得更快**。
图拿来做两件事:**帮自己看懂,也用来配图**。他还问能不能接网页版 GPT 出图。

现在的样子:
- 每天的提醒邮件是纯文字(`lib/domains/signals/notify.ts` 的 `buildDailyEmail`):今日总览一段,五节每节只列标题,
  背景要点开网页才看得到。
- 报告页每条默认一行标题,点开是几段文字。
- 已经有一套代码画图的技术:周刊的小红书封面 `/api/issue-card/[id]`(`next/og` 的 `ImageResponse`,
  颜色取 globals.css 的 token,中文字体按用到的字从 Google Fonts 切子集,拿不到字体返回 503)。

## 不接网页版 GPT

用程序打开网页版 ChatGPT、替他登录、点按钮出图:OpenAI 的使用条款不许程序自动操作网页版,账号可能被封;
网页一改版就坏。和"小红书不自动发帖"同一个理由。出图走 Gemini 的图片模型(下面第三块),出不来再退回
"系统写出图提示词、他自己复制进网页版 GPT"。

## 一、一图看懂(看懂用,代码画,不用 AI 出图)

每条精选配一张小图:四个框加箭头 ——

```
起因 → 发生了什么 → 谁受影响 → 接下来盯什么
```

- **字从哪来**:报告生成时"读正文重写"那一步(`groundBrief`,已经读了正文)顺手多写一个 `flow` 字段,
  四个框各一句,每句不超过 18 个字。不多调一次 AI,早上 60 秒的定时任务装得下。
  没读到正文的条目(只根据标题和简介写的)不画。
- **核对**(代码):
  - 框里的数字必须在那一条的正文里出现过(`numbersIn`),有一个对不上整张不画;
  - 框里不许有下结论的话(`isCommentSentence`、SIGNAL_BANNED),"接下来盯什么"必须是一件看得见的事
    (谁、做什么、什么时候),不许写"值得关注""持续观察";
  - 四个框都要有,缺一个整张不画。
- **画法**:
  - 报告页:点开一条,背景上面先是这张图,用 HTML/CSS 画(四个框、箭头、语义 token 的颜色),手机上竖着排;
  - 邮件:同样的版式用 `ImageResponse` 画成 PNG(颜色、字体同封面图);
  - 不让 AI 画:AI 画的图,里面的字和数字没法核对,画错了看不出来。
- **存哪**:`BriefItem.flow?: { cause, event, affected, watch }`,跟着条目存在 signal_briefs 里,不加表。
  旧报告没有这个字段,不补画。

## 二、邮件改成带图的版本

- 改成 HTML 邮件,纯文字版照旧一起发(看不了 HTML 的邮箱显示纯文字)。
- 从上到下:
  1. 今日总览(和现在一样);
  2. **最值得点开的 3 条**(今日总览挑的那三条):标题、两三句背景、一图看懂;
  3. 五节各条:标题 + 一句话(背景的第一句);
  4. 今天的练习、到期的判断、在追的问题、周五周刊提醒、周一慢变量(和现在一样)。
- 图片作为邮件附件嵌进正文(`cid:`),不用登录就能看,也不用给图片开公开链接。
- 邮件 HTML 只用表格和行内样式(邮件客户端不认 CSS 变量和 flex),颜色抄 globals.css 的 token 值。
- 画不出图(字体拿不到、那一条没有 flow)就只发文字,不拦着发邮件。
- 时间:7 点的定时任务先生成报告再发邮件,画 3 张 PNG 预计几秒;写计划时先在本机量一次。

## 三、AI 示意图(配图用,点了才出)

- **在哪**:一条讲透页①那一节,和周刊挑条时每条旁边,一个「出一张配图」按钮。不进每天的报告(每天几十张,又慢又花钱)。
- **怎么出**:用现在的 Gemini key,走图片模型(模型名读 `AI_IMAGE_MODEL`,默认 `gemini-2.5-flash-image`,写计划时先试);
  传输照规矩走 `lib/ai-gateway.ts`,新增一个出图的入口(和文字调用一样记加密日志),不在别处 new GoogleGenAI。
- **提示词由代码拼**:那边是什么(headline、这一类东西的叫法),画成一张示意插画;
  固定的要求由代码加:不写任何字、不放数字、不画真实公司的 logo 和产品界面、不画真人的脸、3:4 竖图。
- **存下来**:图存进 Supabase Storage(新 bucket `signal-images`,不公开,页面用服务器签的临时链接显示);
  记录存新表 `signal_images`(迁移 084):user_id、side、signal_id、storage_path、prompt、model、created_at。
  同一条可以重出,旧的留着,页面显示最新一张,可以下载(给小红书用)。
- **标注**:图下面固定写「AI 生成的示意图,不是实拍、不是产品截图」;他自己看过才拿去用。
- **出不来时**:模型调不通、这个 key 用不了图片模型 —— 按钮改成「复制出图提示词」,他贴进网页版 GPT 自己出。

## 不做的

- 不自动操作网页版 GPT、不登录任何外部网站。
- 不让 AI 画任何带数字、带字的图(图表、信息图、产品截图)。
- 不给旧报告补画一图看懂。
- 不在每天的报告里自动出 AI 示意图。
- 不打分。

## 怎么判断有没有用(照项目规矩先写下)

- **用的时候碰到的**:早上看邮件只有标题,要点开网页才知道讲什么,看得慢。
- **对账草稿(他改了再押进判断账本)**:到 11 月 1 日,有至少 5 个早上只看邮件就决定了点开哪一条(或者一条都不点)。

## 写计划时要先试的

1. Gemini 图片模型用现在的 key 能不能出图、一张多久、多少钱(试一张,出不来就只做"复制出图提示词")。
2. `ImageResponse` 在 Node(定时任务那边)能不能画 PNG、带中文字体要多久。
3. Gmail 收到的 HTML 邮件里,`cid:` 图片显示正常。
