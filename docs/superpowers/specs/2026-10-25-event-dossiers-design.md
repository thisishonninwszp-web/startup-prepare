# 外部信号：事件档案设计

## 目标与边界

把每天读到的材料积累成可以追踪、核对和回看的事件档案。用户持续阅读时，能够知道一件事发展到了哪里、哪些解释站得住、哪些问题仍没有答案，以及自己的理解如何改变。

本设计覆盖用户认可的十一项能力。跨天时间线属于事件档案的基础视图，不另建一个产品。现有“今天、记忆、预测、机会、行动”导航继续沿用，事件档案从新闻详情和追踪区进入，索引归到“记忆”。

用户明确要求暂不动锁定机制：本项目不改三天锁定、不增加使用限制、不强迫读新闻后创建预测或行动、不新增想法评分，也不改变五个想法状态。新增的数据结构描述来源关系和事件研究，不重分类 validations 的 has_pain / will_pay。

## 用户体验

读到新闻 → 点“追踪这件事” → 系统给出可能相关的报道 → 用户确认归入事件或新建 → 打开事件档案。

档案第一屏回答：这是什么事、最近报道新增了什么、仍然不知道什么、下一个已知节点是什么。下面是时间线。竞争解释、原始来源关系、观察窗口等按需展开。

未确认的自动聚合只显示在“可能相关”，不混入档案事实。用户能移出误归报道、修改事件名称，并保留归类修订记录。不同事件可以有关联，但不能因“都谈利率”就自动合并。

只有时间线和原始引用时，档案已经有用；AI 分析缺失、失败或尚未生成时，不阻塞阅读。新分析通过用户主动请求或明确的后台刷新任务生成，不因打开页面自动启动昂贵搜索。

## 能力清单与完成定义

| ID | 能力 | 用户获得什么 | 完成定义 |
|---|---|---|---|
| F01 | 事件档案与跨天时间线 | 一次看懂起点、进展、争议和下一步 | 稳定事件ID，报道可确认加入/移出，分页回看，旧档案版本可查看 |
| F02 | 预期落空 | 看见原先推理中被现实挑战的前提 | 预先保存预期、期限和判定条件；到期允许确认发生/未发生/尚不知道，不拿没搜到代替没发生 |
| F03 | 竞争解释 | 同时保留几种讲得通的解释 | 每条解释有成立前提、可区分观察及来源；新材料可关联支持或挑战，AI归类待确认，不排名不打分 |
| F04 | 新闻暗线 | 发现不同事件之间值得核查的联系 | 跨事件链的每条边标出依据和推断；无出处的关联留在候选，能指出反证与替代解释 |
| F05 | 理解变化回看 | 看清自己为什么改判、哪些理解未更新 | 从本人真实笔记/判断/修正中生成，引用具体版本；没有记录就说没有，用户决定是否保留回看 |
| F06 | 来源家谱 | 分清转载扩散与独立材料 | 展示明确引用/转载/原始发布关系，未知留空；同一域名不代表同一源，不同域名不代表独立证据 |
| F07 | 两只时钟 | 分清现实变化与消息重新传播 | 显示事件时间、发布、抓取、首次打开的区别及出处；时间不详就标不详，不用抓取日期冒充发生日期 |
| F08 | 新闻时光机 | 在指定日期的信息边界内回看判断 | 冻结材料包、截止条件和逐步揭晓；正文/链接/导出/搜索都过时间门；明确回放覆盖限制与AI未来知识污染 |
| F09 | 现实观察窗口 | 持续看贴近问题的原始变化 | 保存公开来源、观察字段、检查节奏和快照；检查失败不等于没变化；网页改版可重设，历史不覆盖 |
| F10 | 换位阅读 | 看同一事件对不同人的约束与选择 | 顾客/员工/经营者/供应商为阅读视角，不冒充本人观点；每个结论有材料，缺证据则只生成待问问题 |
| F11 | 未知清单 | 知道还缺哪块信息 | 问题有明确缺口和解答条件；可追加来源及答案，用户确认补齐/不再追问；旧空白与答案历史保留 |

## 共同数据规则

### 所有权

第一版事件档案采用私有工作区：每个事件归当前 viewer 的 user_id，新闻来源继续复用已有公开/共用材料。这样事件名、归类、笔记、解释、预期和未知都不会因共用报告泄露给其他读者。

共享正文 sourceUserId 只用于读取共用报道，不用它保存私人档案。服务端从会话取得 viewerId，所有对象按 user_id 校验；RLS之外继续校验外键对象归属，因为当前服务端使用 service role。

未来如需公开事件资料，另做显式分享及去私有字段序列化；这轮不把私人事件直接改成公共资源。

### 事件身份与纠错

稳定 UUID 是事件身份，标题与 event 短标签是可修改的展示和候选匹配信息。已有向量、关键词、same-story规则只提候选，不自动证明同一事件。

归入/移出采用追加修订。所有历史摘要固定引用当时的成员快照，移出报道后旧摘要不重新编造。第一版支持移出和新建另一事件；批量合并/拆分在有真实重复案例后再做专门迁移工具，不以直接修改FK代替。

### 来源、主张与摘录

保存可追溯的 URL、标题、发布方、抓取时刻、内容哈希、实际捕获的摘录与覆盖范围。没有全文访问能力就只保存已取得的范围，不把摘要伪装成完整原文。

AI输出引用档案内 sourceSnapshotId + quote，而非任意生成URL。服务器验证引用属于当前档案及允许的时间范围，摘录出现在对应快照中；引用校验失败时保留用户输入、拒绝发布该分析。

多个支持主张如果都来自同一公告，不增加独立来源计数。引用关系只在有明确链接/声明/可验证引用时确认；相似文本只能提出“可能转述同源”，人工或后续证据确认。

关系属性（引用/转载等）是来源关系，不是把验证证据分为强弱等级。来源数量只用于说明材料来路，不能汇总成想法分数。

### 时间

每条材料至少保留 published_at（允许空）和 captured_at。事件发生时间单独保存为日期/区间及原文出处，可标精度为日/月/年，未找到则为空。它不由发布时间推算。

首次看到时间来自 viewer 自己的 signal_opens.first_at；当前打开历史缺失或早期日志未启用时，展示“系统记录的首次打开”，不宣称真正第一次知道。界面统一按 Asia/Tokyo展示，存储采用带时区时间戳，事件仅有日期时不伪造时分秒。

### 历史与回放

快照追加保存，不回写过去抓取的内容。记录“历史材料今天补录”和“当时系统已保存”两种不同时间来路。

F08提供两种明确入口：

- 系统当时档案：只读在截止时刻前已经捕获的版本；覆盖可能稀疏，绝不补后来的材料。
- 回溯补录材料：来源声称发布于截止前，但系统后来才获取；单独标识，不能当成严格盲测。

回放默认不请求实时搜索，不载入最新事件标题/摘要，不预取未来节点，未揭晓前不直接链接可能包含后来更新的外部网页。使用保存的允许版本；历史更正若当时未知，也不可提前显示。

现代大模型可能在训练中知道结局。第一版回放聚焦用户自测和材料揭晓；AI只能辅助整理给定档案，不把其表现称为无污染的历史预测评测。真正模型比较需要冻结测试集、可审计输入和独立评估设计。

## 信息架构与实现边界

一个事件入口，内部五个区域：概览、时间线、解释与预期、来源与未知、观察。理解变化在现有周报增加板块；时光机是事件页的独立回放模式。

新领域代码放到 `lib/domains/signals/events/`，AI封装放到 `lib/ai/signal-events.ts` 并由 `lib/ai/index.ts` 导出。不继续扩大 `lib/ai/signals.ts`，不复制 article、sources、ai-gateway 的抓取与核验逻辑。

自动分析分成短任务：保存先完成；抓取/关联/摘要分别记录处理状态与错误。对相同输入哈希和prompt版本复用结果，请求重试使用客户端请求ID；单次任务先限制候选数与来源数，失败可重试，不在页面请求中无限补抓。

第一版历史回填只回填元数据和可获得摘录，保留补录时间。不得对所有历史新闻自动发AI生成和搜索。首批使用用户选中的3个事件检验聚合与阅读，再逐步覆盖。

## 交付顺序

1. A期：F01 + F07，建立事件身份、快照、双时间和跨天时间线。
2. B期：F06 + F11，建立来源关系与未知清单，档案概览以引用为基础。
3. C期：F03 + F02 + F10，加入竞争解释、预期检验和换位阅读。
4. D期：F09 + F04 + F05，接原始观察窗口、跨事件关联和个人理解变化。
5. E期：F08，在版本与时间边界稳定后实现历史回放。

每期独立验收、迁移、部署。A期完成即可投入日常使用，不等待全部十一项。用户本轮只要求写计划，没有授权立即开始本路线图实施或自动发布。
