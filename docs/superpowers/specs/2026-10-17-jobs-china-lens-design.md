# 「御社の商売、中国ではどうなっている？」设计文档 —— 面试时给面试官当场用的演示

日期:2026-10-17
状态:待用户审阅本文档

## 背景

用户在找工作(见 `2026-10-16-jobs-design.md`)。他想要"为了面试能做出一些看起来很牛逼的、可以给面试官展示的网页",
而且要"实际让面试官可以用的东西",不只是作品集。

先提过"AI 搜索里御社怎么被介绍"。用户说那是公司里做过的事,不用管,要"有什么好的"。
于是换成这个:面试官说一句他们做什么生意,页面用中文去查中国做同样生意的公司,把原文、日文翻译、出处摆出来,
再查那边做成靠的条件在日本有没有、有没有中国同行已经来了日本。

## 用户的原话与选择(2026-10-17)

- "我的想法是为了面试能不能做出一些看起来很牛逼的,然后可以给面试官展示一下的网页之类的"
- "我想的干脆是做一个实际让面试官可以用的东西之类的。当然作品集确实好像也不错"
- 对 AI 搜索那个:"这个公司里面的做的。没事,不用管这个。我想的是有什么好的"
- 没有 ChatGPT 的 Key,先不接。
- 选了"做「御社の商売、中国ではどうなっている？」,先写设计给我看"。

## 为什么是这个(给面试官看的那一句)

「中国語の一次情報を、出典を確かめながら日本語で持ってこられます」。

- 会读中文、又会核对出处,日本的应聘者里几乎没人能当场演示。四类岗位里"需要中文"那类直接对口;
  咨询和企划给客户做调查本来就要查海外先例。
- 演示的是 IdeaOS 自己的本事(原文逐字核对、数字核对、另一个模型当裁判),不是重做 Focus 里的东西,
  也不碰 Focus 的任何公司数据。
- 不给结论、不打分,只摆出处。面试官追问哪一句,都能点开原文。

## 面试里的样子

面试官:「うちは中小企業向けに勤怠管理のSaaSをやっています」。
他在页面上输入这一句,点「中国で調べる」:

1. 几秒后先出现用的中文搜索词(「中小企业 考勤 SaaS」「考勤打卡 软件 融资」……)。
2. 二三十秒后出现「中国で同じ商売をしている会社」两到四家:每家一行日文说明它做什么,一句中文原文,
   下面是 AI 翻的日文,原页面的链接。
3. 再二三十秒出现「中国でうまくいった条件は、日本にもあるか」三到五条,每条标「ある / ない / 資料なし」,
   「ある」「ない」都附日本这边资料的原文;最后是「中国の同業は日本に来たか」:谁、什么时候、结果怎样(附原文),没查到就说没查到。

前后一分钟左右。面试前一晚,他也可以先拿那家公司的生意跑一次,当准备材料读;面试中现场跑失败了,就打开前一晚那次的结果。

## 页面

- 地址 `/demo/china`(只有输入框)、`/demo/china/[id]`(一次的结果)。
- **跑过的记录放在 `/jobs`,不放在演示页上**:演示页共享给面试官看,列着的记录会让对方看到他还查过别家的生意。
  `/jobs` 的入口那一节下面列最近 20 次(那一句 + 日子 + 跑完没有),点开就是那次的结果页。
- **不带导航壳**:新建路由组 `app/(present)/`,像 `(print)` 那样不挂 AppShell。
  共享屏幕时不会露出侧边栏里"梦想""自我"这些他私人的东西。要登录(middleware 现在就会挡没登录的),
  只有他自己操作,所以符合"陌生人能触发的动作一律不调 AI"。页面右上角一个小链接回 `/jobs`。
- **界面是日文**(给面试官看)。`/jobs` 页加一行入口(中文):「面试时给对方当场用:御社の商売、中国ではどうなっている？」。
- 容器用 `PageContainer` default;按钮、徽章用共享组件;只用语义 token。

### 文案(日文,同样过"说人话"五条:短句、写场景、不夸、不打气)

- 输入框:「御社の商売をひとことで」,placeholder「例:中小企業向けの勤怠管理SaaS」;按钮「中国で調べる」。
- 进行中:「中国語で検索しています:<搜索词>」→「見つかったページを読んでいます」→「日本でも同じ条件がそろっているか調べています」。
- 三个小标题:「中国で同じ商売をしている会社」「中国でうまくいった条件は、日本にもあるか」「中国の同業は日本に来たか」。
- 原文旁:「原文(このページにそのまま載っていることを確認済み)」;译文旁:「AI訳」。
- 裁判:「同じ商売かどうか、別のAIでも確認済み」/ 裁判没调通时「別のAIの確認はまだ」。
- 条件那边:「中国では(AIの説明・出典なし)」「日本では」+ 原文;徽章「ある」「ない」「資料なし」。
- 一家都没找到:「見つかりませんでした。もう少し具体的に書くと(誰に・何を売っているか)、見つかることがあります。」
- 页脚(固定,代码加):「検索で見つかったページだけを読んでいます。読めなかったページの会社は出てきません。
  同じ言葉で調べても、毎回少し結果が変わります。良し悪しの判断はしていません。」

## 怎么查(三步,每步一个 server action,各自 60 秒内;浏览器按顺序接着调)

Vercel 一个请求最多 60 秒,整个流程要一分钟多,所以拆成三步。每步做完存进数据库,下一步从数据库读上一步的结果
(不信浏览器传回来的内容)。好处是面试官每二三十秒就看到新东西,中间哪步失败,前面的结果还在。

### 第 1 步:搜索词(AI 一次,约 5–10 秒)

输入他填的那一句。AI 写:
- `zh_business`:这门生意在中国的说法(一句中文,例:「面向中小企业的考勤管理 SaaS」);
- `queries`:2–3 个中文搜索词,用中国那边的说法,不直译日文(例:勤怠管理 → 考勤;SaaS 照留),
  其中一个带"融资"或"上市"这类词,容易搜到讲公司的报道。

代码查:搜索词是中文、2–3 个、每个 3–8 个词以内。

### 第 2 步:中国的公司(搜索 + AI 一次 + 裁判一次,约 30–45 秒)

1. 几个中文搜索词并行 `webSearch(q, 6)`(Google 找网页、代码自己读正文,失败退 Tavily;规矩照 CLAUDE.md)。
2. AI 从这些资料里挑最多 4 家做同样生意的公司,每家写:
   - `name`:公司或服务名,照资料里的写法;
   - `what_ja`:它做什么,一句日文;
   - `excerpt`:资料原文,逐字照抄(15–150 字),附资料编号;
   - `excerpt_ja`:这句原文的日文翻译。
3. 代码核对(不合格的那家丢掉,不重写):
   - `excerpt` 逐字在那篇资料的正文里(去空白比较,和 `verifiedBasis` 同一套);
   - `name` 出现在那句原文或那篇资料的标题里(防编公司名);
   - `what_ja`、`excerpt_ja` 里的数字和英文词必须在原文里(`provenance-shared.ts` 的 `unsupported`);
   - 日文字段要有平假名;不许有夸奖、"チャンス""有望""ポテンシャル""期待でき""注目すべき"这类词;
   - 同名的只留一家。
4. Jev 判每家:「这句原文写的是不是这家公司在做 `<zh_business>` 这门生意」(两档,门槛 0.5)。
   判"不是"的丢掉;Jev 没调通照留,标「別のAIの確認はまだ」。

一家都没剩:状态记成"没找到",页面给"没找到"那句和用过的搜索词,不进第 3 步。

### 第 3 步:日本这边(AI 两次 + 搜索,约 30–45 秒)

1. AI 看第 2 步留下的公司,写:
   - 这些公司在中国做成靠的 3–5 个条件:`name`(短名)、`there_ja`(中国那边的情况,一句日文,
     **不许写数字**:这句没有出处,代码查到数字就重写)、`query_ja`(查"日本现在这一条怎样"的日文搜索词);
   - 要特意找日本**可能没有**的条件(原则 2:找它搬不过来的理由),不只列顺的;
   - `entrant_queries`:两个搜索词:日文一个(「中国 <业种> 日本進出 撤退」这类,退出的也要)、中文一个(「<业务> 出海 日本」)。
2. 并行搜:每个条件 `webSearch(query_ja, 3)`,先例两个词各 `webSearch(q, 4)`。
3. AI 判每个条件:`here_ja`(日本现在怎样,一句)、`holds`(ある / ない / 資料なし)、`basis`(日本资料原文逐字,附编号);
   来过日本的中国同行:最多 3 件,每件 `text_ja`(谁、什么时候、结果怎样,一句,包括退出的)+ 原文。
4. 代码核对:拿不出逐字对得上的原文 → 这一条一律「資料なし」,`here_ja` 换成「日本側の資料が見つかりませんでした」;
   先例没有原文 → 当没查到;日文字段的数字必须在对应原文里;同样查平假名和禁用词。

和差距清单"能不能搬过来"是同一个思路,但那边的提示词输出中文、存在 `signal_gap_transfers`,
这里另写一份输出日文的,原文核对的函数(`verifiedBasis`)从 `lib/ai/signals.ts` 导出来共用,不复制。

## 不做的

- 不打分、不排名、不写"御社にとってのチャンス""参考になる"这类结论;"ある/ない"的个数也不数。
- 不给面试官开不用登录的公开页(会调 AI,会被刷钱)。
- 不碰 Focus-Yamanashi 的任何数据和代码。
- 不接 ChatGPT(没有 Key);以后要接再说。
- 不做"把结果发给面试官"(邮件、链接分享)。要的话以后再说。

## 数据

迁移 `080_job_china_runs.sql`(同步追加到 `supabase/schema.sql` 末尾,CRLF):

```sql
create table if not exists job_china_runs (
  id uuid primary key default gen_random_uuid(),
  user_id uuid not null references auth.users(id) on delete cascade,
  business text not null,          -- 他输入的那一句
  status text not null default 'planned'
    check (status in ('planned', 'companies', 'done', 'none_found', 'failed')),
  plan jsonb,                      -- 第 1 步:zh_business、queries
  companies jsonb,                 -- 第 2 步:留下的公司(带原文、出处、裁判结果)
  japan jsonb,                     -- 第 3 步:条件、先例
  error text,                      -- 哪一步、为什么失败(给页面显示)
  created_at timestamptz not null default now(),
  updated_at timestamptz not null default now()
);
create index if not exists job_china_runs_user_created on job_china_runs (user_id, created_at desc);
alter table job_china_runs enable row level security;
create policy "job_china_runs_owner" on job_china_runs
  for all using (auth.uid() = user_id) with check (auth.uid() = user_id);
```

迁移没跑时页面显示"迁移 080 还没跑"那句(和 078/079 同样的写法),`/jobs` 其他功能不受影响。

## 失败时

- 每一步失败:存 `status='failed'`、`error` 写哪一步,页面保留前面几步的结果,给「もう一度」(从失败的那一步接着跑)。
  失败的是哪一步按哪几列是空的来认(`plan` 空 → 第 1 步,`companies` 空 → 第 2 步,否则第 3 步),不另存一列。
- 中国的网页常常读不到(要登录、脚本画的):读不到的那篇不算,页脚已经写明。
- 面试中现场跑不出来:从 `/jobs` 的记录里点开前一晚跑好的那次(先在自己屏幕上点开,再共享)。

## 宪法

- 不加导航、不加模块:是 jobs 下的一个工具页。CLAUDE.md 的 jobs 那一行补一句:
  「面接で見せる「御社の商売、中国ではどうなっている？」(/demo/china,无导航壳,迁移 080):
  面试官说一句生意 → 中文搜索 → 中国同业(原文逐字核对、日译的数字和英文词必须在原文里、公司名必须在原文或标题里、
  Jev 判是不是同一门生意)→ 那边做成靠的条件在日本有没有(日本原文核对,没原文一律資料なし;中国那边的说明不许写数字)
  → 中国同业来没来日本(含退出);界面日文,不打分不下结论,要登录、只有他操作」。
- AI 模块用 `"jobs"`(`AiModule` 里已有)。

## 测试

- 解析器(vitest):原文不在资料里的那家丢掉;公司名不在原文/标题里的丢掉;日译多出数字的丢掉;
  没有平假名、带禁用词的报错重写;条件没原文变「資料なし」;`there_ja` 带数字报错重写;先例没原文变 null;同名去重。
- 状态:每个状态的下一步对(planned → 第 2 步,companies → 第 3 步,done / none_found 不再跑,failed 从失败那步接着)。
- 验证照项目约定:`npx tsc --noEmit` + `npm run lint` + `npm test`,dev server 开着时不 `npm run build`。

## 先试再做页面

写页面之前,先用一个本地脚本(scratchpad 里,不进仓库)拿三门不同的生意跑第 1–3 步:
「中小企業向けの勤怠管理SaaS」「地方の工務店」「中古ブランド品の買取」,看每门留下几家公司、几条条件有原文、每步几秒。
中国网页读不到太多、一家都留不下的话,先改搜索词的写法或每个词多搜几篇,再做页面。

## 用的时候会碰到什么、怎么算有用

- 用的时候:面试前一晚,拿那家公司的生意跑一次,读完挑一条能当场问的;面试里被问"有什么想问的""你的强项"时,共享屏幕现场跑。
- 算有用:到 2026-11-16,至少在 1 场面试里现场跑过,并在那家的投递记录里写一句面试官的反应。
  一次都没跑过就是没用上 —— 回头看是没机会拿出来,还是结果太差不敢拿。

## 考虑过、没选的做法

- **一次跑完、用流式输出**:整个过程还是一个请求,照样卡在 60 秒,而且中途失败什么都留不下。
- **只在面试前跑好、面试时只给看**:稳,但丢了"面试官当场用"这一点,就退回成作品集了。
