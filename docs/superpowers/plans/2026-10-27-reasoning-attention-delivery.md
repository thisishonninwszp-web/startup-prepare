# P5 来源纠错、解释质量与注意力管理交付

2026-10-27。本期本地实现完成；未提交、推送、执行远端迁移或部署。继续沿用已有功能分支与未提交依赖；未改用户的 `.claude/launch.json`。

## 入口和操作

开启功能后，在事件档案详情的已有研究/回放下方打开“推理与来源纠正”或“阅读约定与固定留样”。两个面板均由用户主动读取，未添加全站导航，不影响原来的新闻阅读和捕捉。

| 能力 | 本期行为与边界 |
| --- | --- |
| 信息增量 | 选基准和新材料的逐字引用，分别记录新增事实、来源独立性及依据；转载可以有新增事实，不自动跳过相似报道 |
| 分母缺口 | 并列保存样本、群体范围、分母和遗漏群体；未知必须明确，不把新闻样本当市场比例 |
| 数字比较 | 核对统计定义、单位、周期、地域、名义/实际、金额/数量；缺失或声明口径不同不能保存为可比，不自动换算 |
| 分歧与传导链 | 保存双方原话、分歧原因和核对问题；每环有引用、反例或未知，首环有材料不表示末环已发生 |
| 类比适用条件 | 保存关键条件、失效条件与后续核对；用户选择原记录追加复查，不自动判定跨地区/行业成立 |
| 来源更正 | 选择旧/新快照的具体原话；生成原结论的不可变影响提示。支持同owner跨事件引用、推理依赖、研究父子关系、noteRefs和已冻结selectedNoteIds/selectedSnapshotIds，以及后续新增引用 |
| 纠错回执 | 提示同时显示更正原文与受影响原结论；确认已查看不覆盖历史，需要变更时另追加判断。归档事件仍可读旧记录，不能新增推理 |
| 阅读约定 | 保存值得提醒的变化、不能忽略的反例和留样规则；可改版、退出。材料匹配由用户人工核对，未匹配/未知不隐藏，不新增通知或自动过滤 |
| 固定留样 | 从每版首次主动登记开始，按预先保存的每N次留1条，第一条必留；看到/打开/跳过/待判断都进入登记序列，不把页面加载当曝光，不回填过去行为 |
| 自愿先读材料 | 固定样本可先读冻结材料、写判断，再揭晓标题，或直接退出。初始DTO不传标题；揭晓后不能补先判。原页面始终可访问，用户可能先前已见标题，不能据此声称科学盲测 |

来源选择支持翻页读取事件曾保存的材料，原文单独加载并显示捕获范围；不只开放最近100条。P5只检查明确引用与依赖，不按自由文本里出现的ID猜关联。

## 数据与一致性

新增推理、纠错影响/请求回执与阅读约定日志/请求回执。owner校验、引用归属、逐字引句、版本和规则均在数据库重查，记录不可覆盖。

纠错及影响提示原子保存，任一步失败都会回滚；未来引用旧来源也会追加影响提示。114保留106原研究函数的完整校验，将旧函数改名并撤销直接执行权限，同名入口仅增加owner写入序列锁；新研究记录触发追溯。跨事件并发遵守相同锁顺序，避免更正与后来引用相互漏看。

固定留样由服务器序号决定，每个快照每版只登记一次；重复登记保留首次选择，不伪造后续曝光。规则改版保留旧版本/样本。先判、退出、揭晓在数据库强制排序；同一样本再次开始返回原会话，避免重开会话伪装“尚未见过”。阅读原始表禁止普通authenticated和service_role直接读取，以受控DTO提供未揭晓材料。

没有新增AI调用、外部数据抓取、消息发送、后台调度或想法评分；不创建validation，不改想法状态、last_activity_at或锁定机制。阅读匹配不是需求信号或证据强弱等级。

## 迁移和开启

1. 确认105/106及其既有依赖已经存在。
2. 执行 `supabase/migrations/114_reasoning_quality.sql`。
3. 执行 `supabase/migrations/115_reading_attention.sql`。
4. 部署代码后，确认 `SIGNAL_EVENTS_ENABLED=true`，再开启 `REASONING_ATTENTION_ENABLED=true`。新开关默认关闭，缺迁移时相关面板显示不可用，旧页面保留。
5. 实际账号验收通过前不要视为上线完成。可运行只读结构检查 `node scripts/check-schema.mjs --reasoning --events`；新增reasoning模式检查2个可读表、4个RPC及空owner拒绝。阅读原始表故意不开放，不能以直接SELECT作为健康检查。

回退时关闭新开关，保留日志和快照。关闭UI不会删除114追溯触发器；既有研究写入继续保留来源更正影响。没有执行破坏式回退SQL。
