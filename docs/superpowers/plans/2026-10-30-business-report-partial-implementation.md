# 生意拆解逐条校验 Implementation Plan

用户于2026-10-30批准保留通过校验的部分并明确标缺口，继续既有上线授权。

**Goal:** 单条不合格内容不会吞掉可核对的其余内容，不展示被剔除文字，不自动重试。
**Architecture:** 原始模型结构仍严格校验；逐条复用现有语义/引用规则，失败项仅保存固定规则代号、字段和条数。缺口存现有sections JSON，无新迁移；保存前再次校验，界面明确报告不完整，没有有效解释的部分报告禁止发布。
**Tech Stack:** Next.js 14、TypeScript、Zod、Supabase、Gemini。

- [x] 测试：混合有效/无效解释、数值引用、未知项；整体结构错误拒绝、被剔除正文不留存、二次校验保留缺口。
- [x] 领域实现：独立过滤器与缺口类型，严格保存校验，手动生成保留部分报告；原模型不允许声明缺口。自动任务原事务同时保存并发布，本次仅增加遇到缺口时停止的保护，不宣称可保留自动部分报告；生产自动任务保持关闭。未来启用前需要独立的草稿保存事务与验收。
- [x] 界面与发布：报告头部和各节显示剔除说明，区别于资料未知；禁止发布全无解释的部分报告；补UI/发布行为测试。
- [ ] 验证：相关测试、类型/lint/build；审查保存、发布、单次调用和隐私边界。
- [ ] 发布：保留远端更新；通过正式页面单次公开材料许可→生成→核对→发布→刷新。自动任务保持关闭，不伪造本人方法或真人验证。
