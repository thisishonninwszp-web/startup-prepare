# P3 企业身份与实际行动交付

2026-10-26。本地代码与验证完成；未提交、推送、执行远端迁移或部署。沿用当前功能分支及此前未提交的代码依赖，用户已有.claude/launch.json未修改。

## 已实现

- 企业详情内新增默认折叠、按需加载的研究面板，关闭开关/缺新表时保留原企业档案。
- 人工身份预览、明确确认、撤回和不可覆盖的历史。法人番号要求13位，未声称仅凭格式即已验证有效性；官方查询与用户导入明确区分。
- 同一用户重复法人绑定拒绝，品牌/分支/母公司不自动合并。身份采用单调revision，确认带预期版本，版本变化清除旧预览；不覆盖原企业名称和私人笔记。
- 国税厅XML与Gビズインフォ v2身份、采购/补助的固定官方域名适配器。8秒超时、响应上限、拒绝重定向、无凭证明确不可用；未使用官方演示令牌。
- 官方响应再次读取、核对所选语义指纹后才保存；重复请求先返回此前已保存结果，避免响应丢失后因网页或API变化重复写入。
- 结构化人工JSON导入，明确资料范围和未在线核验性质。金额0、未知金额和未知币种分别保存，补助的描述性金额不随意解析成数值。
- 活动分开记录宣布、行动、结果，每项独立附原文/来源；宣布不自动推进为执行或经营效果。用户可写项目字段，未记录后续只表示尚未观察到，不证明没有后续。
- 已保存岗位按已有公司档案关联、仅同名人工候选分区；候选需勾选确认。保存核对预览哈希并复制服务器当时原文，长原文明确裁剪范围并保留原始/捕获哈希，不复制成新岗位，不声称已雇佣或有软件采购预算。
- 竞品价格/功能的人工快照和公开网页片段核对保存。自动读取复用现有安全抓取的地址/DNS/重定向/大小限制；失败和找不到标记不生成价格/功能事实。
- 仅在同一档案、URL、产品/方案、地区、单位、币种和捕获范围一致时比较所选文字；价格单位或币种未知不可直接比较，不自动推断涨跌、客户需求或产品效果。
- 企业材料明确关联本人想法，保存“复查哪条假设”和“仍未知什么”，公司和想法两端都能查看原文、出处及历史。不写validations、不改想法状态或活动计时，不新增/改写锁定机制。
- 旧想法可搜索及分页，岗位分区可继续读取，历史游标保留PostgreSQL微秒精度。顺手修复同类观察任务游标精度问题，新增回归测试。

## 有意保留的边界

1. **凭证未配置，因此没有真实官方业务API联调。** 适配器使用官方规格与合成响应测试，不能据此声称已获取真实公司活动。用户仍可人工录入/导入。
2. **EDINET为人工披露路径。** 指定文件接口提供PDF/ZIP，不能直接返回可核对的法人JSON。界面明确显示在线核对不可用，允许通过披露活动或人工JSON保存有出处材料；未编造元数据接口或自动解析全部文件。
3. 已有岗位company_id是应用内关联，不等于岗位页独立证明法人番号；同名候选尤其需要人工核对。没有对所有新闻、品牌或招聘主体做自动实体合并。
4. 网站快照是最多600字符的提取片段，不是完整网页档案；失败/动态页面/变化后的二次抓取要求重试或人工核对。
5. 想法页显示最近20条已关联复查问题，更多资料在企业历史查看；不会自动判断这些问题已解决。
6. 不调用新的AI分析，不自动联系企业、发消息、投广告或建立后台抓取任务。P4–P6仍是后续计划。

## 数据库与配置

执行 `supabase/migrations/110_company_observations.sql`，增加私人追加日志及服务端RPC。新功能不依赖105–109的表，但代码复用了先前新增的安全网页抓取和表单请求身份模块，发布必须包含代码依赖。

首次迁移包含 `begin`/`commit`，非可重复创建脚本；成功后不要重复执行。执行前核对Supabase目标项目。只读验收命令：

```powershell
npm run db:check -- --companies
```

检查新表字段及RPC空owner拒绝，不创建业务记录。

开关：`COMPANY_OBSERVATIONS_ENABLED=true`，默认关闭。服务端凭证：`NTA_APPLICATION_ID`、`GBIZ_API_TOKEN`；EDINET入口可识别 `EDINET_API_KEY` 是否存在，但本期不会自动下载/认定文件。不得将这些凭证放入NEXT_PUBLIC变量。

发布顺序：确认目标项目→执行110→结构检查→测试环境开启→双账号和实际资料验收→生产部署及开启。回退关闭开关，保留数据，不删表。
