# P3 企业身份与实际行动执行计划

> **For agentic workers:** 使用subagent-driven-development实施后端、来源适配、UI三个独立单元，先测试再实现、分别复核。本轮不提交已有未提交文件、不执行生产迁移或部署，不修改想法锁定政策。

**Goal:** 从企业档案核对法人身份，保存实际招聘、采购/补助、竞品与披露材料，将有出处的变化明确关联到需要复查的想法。

**Architecture:** 在现有companies上增加私人、带版本与不可覆盖出处的研究记录；公司名称只产生候选，身份绑定需要用户明确确认。复用现有job_postings和公开网页安全抓取；官方接口仅使用配置凭证，无凭证时可人工粘贴/导入，不假装已在线查证。

**Tech Stack:** 保留Next.js14、TypeScript、Tailwind/shadcn、Supabase、Vercel。此期不新增AI调用，不创建通用图数据库。

**完成状态：** 本地P3流程已实现并验证，见[交付说明](2026-10-26-company-observations-delivery.md)。官方凭证未配置，无真实API业务调用；EDINET本期明确为人工披露路径。远端迁移110及发布未执行。

## 已确认的基础

- 企业档案来自companies（knowledge/queries.ts），已有公司大事记、笔记和求职触达。
- job_postings保存owner、company_id、company_name、title、body、URL、事实和found_on；只有明确选取的岗位才有company_id。新功能不能用相似名称自动跨公司归属。
- 既有events/windows.ts具有DNS/重定向校验和地址固定，可作为竞品公开页检查的网络边界；失败不能生成降价或下架事实。
- 新迁移使用110；实施时再次确认没有并行迁移占用。
- 目前未配置法人番号/Gビズインフォ/EDINET凭证。官方公开Swagger仅供查规格，其中演示令牌不得用于应用调用。

## 第二单元：公开来源与已有招聘

- [ ] 复用已保存招聘记录，精确company_id的岗位与名称候选分区。用户确认后复制当时岗位快照；岗位删除不抹去历史。不创建重复岗位，不声称已招聘或有外包预算。
- [ ] 国税厅法人番号与Gビズインフォ适配器使用固定官方域名、大小/超时限制、不带凭证重定向、日志不写令牌；缺凭证返回明确unavailable。
- [ ] 支持有界的手动JSON/结构化摘录，区分用户导入、官方响应、网页捕获，身份和数据范围必须能核对。
- [ ] 采购/补助记录保存金额、币种、日期、项目/发布方、实际数据范围和原文；未知为空、空列表不等于全市场零需求。
- [ ] 竞品价格/功能保存原文快照。只比较同一URL/产品/单位/范围的两份成功快照；缺页、失败、找不到标记不解释为降价/取消功能。
- [ ] EDINET提供按指定文件ID的受控适配与原始披露入口；无凭证保留人工材料路径，不扫描全部披露文件，不把公司名称当EDINET身份。
- [ ] 用固定官方规格和合成响应测试解析、错号拒绝、缺字段/零/失败、重定向与无密钥行为，不使用公开演示令牌。

## 第三单元：原企业页面里的可用流程

- [ ] `app/(app)/companies/company-observations-panel.tsx` 挂载到现有企业详情，默认折叠、按需加载，缺表和开关关闭不影响旧页面。
- [ ] 先预览、再明确确认身份；人工导入与在线查询分别说明来源性质。

- [ ] root更新schema只读探针、浏览器夹具、执行记录及交付说明。提交边界排除用户已有.claude/launch.json和临时文件。

## 验证与验收

每个单元先观察失败测试，再实现并复跑。最终运行全量Vitest、ESLint、TypeScript、build；实际SQL测试两个用户/同owner不同公司与想法，验证无validations、idea状态、last_activity_at副作用。

浏览器夹具至少覆盖：身份预览/确认、错号/同名候选、活动出处、岗位复制、竞品比较边界、保存失败与刷新失败、手机溢出和明确复查关联。官方服务无凭证时不执行实机查询，不能将模拟通过称为真实API验收。

最终结果：218文件1576项测试、ESLint/TypeScript/build、实际SQL引擎集成、12项浏览器夹具检查通过。独立复核修复微秒分页遗漏、陈旧身份预览、想法/岗位不可达以及岗位预览漂移。原计划清单保留为设计定义，实际范围按交付说明核对。
