# P4 反馈、跨想法学习与归档复查交付

2026-10-27。本批本地实现完成；未提交、推送、部署或执行远端迁移。沿用原功能分支及前批未提交依赖，未改动用户的 `.claude/launch.json`。

## 使用流程

1. 在想法详情打开“反馈与适用范围”，记录接触笔记或无回复经过，或选择已有真实验证。原始记录与用户解释分开；已有验证的信号由服务器复制为只读快照。
2. 展开一条反馈，查找另一个本人想法，明确填写假设、适用群体与情境、局限、反例与未知，确认关联。撤回追加历史，不删原记录，不把来源的痛点/付费信号复制给目标想法。
3. 在反馈下选择已有观察任务，编辑来源、固定与探索词组、地域/语言/时间及停止条件，写理由并预览逐项差异。确认保存提案后，再采用为新版本。比较条件变化会提示不能直接拼接旧趋势。
4. “带上反馈准备接触”生成可编辑的人工接触提纲，再由用户创建私人画布。提纲围绕最近一次实际任务、替代方案、成本与反例；无回复保留未知。创建时服务器重新检查出处归属。没有发送消息或调用AI。
5. 在归档想法写“学到了什么”、值得再看的变化、核对方法和范围。用户引用新材料并手动核对满足/未满足/未知。满足时在工作台与学习页出现复查提示，每版一次；确认已查看后不再提示该版。想法继续保持归档。

## 数据与边界

- 新表保存反馈、跨想法适用历史、归档条件/材料/提示/回执，以及观察调整提案/采用记录/请求回执。均有owner隔离和不可覆盖日志。
- 观察调整采用在同一事务内调用108保存任务版本并记录采用结果。配置过期或跨想法关系被撤回、重确认后均拒绝旧提案；请求重试和重复采用不会重复建版本。重复采用的新请求ID同样保留回执，不能被其他提案复用。
- 归档材料只检查实际来源字段及逐字引用，支持手动公开材料、本人观察运行的具体记录、本人企业记录。已知合成/AI输入不能触发满足条件。手动材料为用户声明，系统没有自动验证网页真实性。
- 最新一次核对为未满足/未知时隐藏当前提示；之后再次满足可显示原提示，已确认查看则该版持续静默。条件撤回或改版后旧提示失效。没有自动采集、定时检查或外部通知。
- P4不新增真实验证，不写想法状态或last_activity_at，不改变锁定机制，不添加评分，不调用Gemini。已有真实验证入口继续独立使用。
- 私人反馈的新闻AI许可不沿用到P4；P4服务端不发送反馈给AI。以后在既有触达画布主动使用AI功能，仍属于该功能原有流程。

## 迁移与开关

先确认既有迁移已就绪，再按序执行：

| 文件 | 用途 |
| --- | --- |
| `supabase/migrations/111_feedback_learning.sql` | 反馈与适用历史；依赖ideas、validations、outreach_canvases |
| `supabase/migrations/112_idea_reconsideration.sql` | 归档条件、核对、一次提示与回执；观察/企业材料为可选来源 |
| `supabase/migrations/113_feedback_task_adjustments.sql` | 反馈调整观察的提案与原子采用；需要108和111 |

`FEEDBACK_LEARNING_ENABLED=true` 开启P4，默认关闭。观察调整还要求 `DECISION_OBSERVATIONS_ENABLED=true`；企业材料需要110已有相应记录。缺迁移时保留既有页面，相关新功能显示不可用。回退时关闭新开关并保留历史表。

结构检查增加只读参数：`node scripts/check-schema.mjs --feedback`，检查7张表、7个RPC及空owner拒绝；此次没有运行远端检查。P4上线前需执行该检查及实际账号验收，不能将本地测试当作已部署证明。
