# 事件档案 A–E 本地交付

2026-10-25。用户将范围扩展为完成全部五期。原计划保留为设计记录，本文件记录实际交付与环境验收边界。

| 需求 | 实际行为 |
|---|---|
| F01 跨天事件档案 | 新闻加入、档案搜索、范围修正、候选确认、冻结来源和归属历史 |
| F02 预期落空 | 判据、截止日、追加发生/未发生/未知核对；无报道保持未知 |
| F03 竞争解释 | 前提、区分观察、分版本支持/挑战证据，旧证据可查 |
| F04 新闻暗线 | 明确另一事件、两端引用、必要假设、反证、替代解释 |
| F05 理解变化 | 笔记/解释修正，周报真实前后记录；AI只分析主动选中的笔记 |
| F06 来源家谱 | 明确引用/转载声明才建议连接、确认/撤回历史、禁止循环 |
| F07 多只时钟 | 报道发布、发生、保存、首次打开分别记录；未知不猜、补录标注 |
| F08 时光机 | 当时存档/事后补录模式；冻结材料、先判断再揭晓、隔离当前导航、只导出已揭晓内容 |

| F10 换位阅读 | 顾客/员工/经营者/供应商处境、材料引用、待追问内容 |
| F11 未知清单 | 回答判据、开放/回答/关闭历史，回答必须附出处 |

AI包含整理档案、未知、竞争解释、换位追问、暗线、理解变化六种任务。页面加载不调用AI。来源和私人笔记默认均不选；逐次展示Google Gemini接收内容，选择变化重新确认。来源最多前10000字符，笔记最多前1000字符；不自动发送私人事件标题/范围。用户已明确允许选中摘录与自选笔记。引用逐字核验；建议预览后手动采纳，失败保留旧草稿。

## 实现收敛

使用带类型的不可覆盖追加日志 `signal_event_research_entries`，而非每类研究分别建表；服务层和RPC校验类型、父记录、归属、引用与版本。迁移105为事件基础，106为研究及AI任务，107为回放。没有替换技术栈、增加想法评分或修改锁定机制。

阶段开关收敛为总开关 `SIGNAL_EVENTS_ENABLED=true`，默认关闭。观察窗口仅手动检查，cadence代表观察意向，没有自动调度。来源目录和AI选择器先显示最近100份；时间线可翻页，旧引用可直接打开冻结快照。

## 部署顺序

1. 核对目标Supabase项目，依次执行迁移105、106、107。
2. 执行 `npm run db:check -- --events`，检查字段、RPC和空owner拒绝。
3. 部署代码，生产开关仍关闭；测试环境开启，双账号验证隔离、网络重试和回放边界。
4. 对持续事件、应拆开的同主题事件、转载且时间未知事件各验收一次；检查真实Gemini选择范围及引用。
5. 设置 `SIGNAL_EVENTS_ENABLED=true`。回退时关闭开关、保留数据，不删表。
